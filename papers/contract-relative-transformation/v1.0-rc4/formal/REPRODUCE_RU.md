# Проверка и воспроизведение

## 1. Проверить скачанный ZIP

Поместите ZIP и его внешний `.zip.sha256` в одну папку.

macOS:

```bash
shasum -a 256 -c CRTT-v1.0-FULL-ARCHITECTURE-RECONCILED.zip.sha256
```

Linux:

```bash
sha256sum -c CRTT-v1.0-FULL-ARCHITECTURE-RECONCILED.zip.sha256
```

## 2. Проверить полный распакованный комплект

Перейдите в папку `CRTT-v1.0-FULL-ARCHITECTURE`:

```bash
python3 verify_archive.py
```

Нужен только стандартный Python 3.9+. Проверяются точный набор файлов, SHA-256, размеры, согласованность двух верхних манифестов, CRC исходных ZIP и тождество всех 144 файлов канонического пакета принятому оригиналу. Эта команда не вызывает Lean и не устанавливает зависимости.

Проверяйте распакованный комплект до редактирования файлов. Новый файл внутри проверяемого дерева считается изменением состава.

## 3. Отдельно выполнить полный kernel/runtime gate

Исходный runner фиксирует **Lean 4.36.0**, commit:

```text
611c117bfaf7b7ae1cfcf246ce6fba31e8f509e9
```

Также нужны Bash, Python 3 и `shasum` либо `sha256sum`. Сторонняя mathlib в текущем пакете не требуется: единственный внешний Lean-импорт стека — `Std`. Точный toolchain и проверки зафиксированы в `canonical/lean-toolchain` и `canonical/run_verify.sh`.

Команду ниже запускайте в Bash из корня распакованного полного архива. Журнал пишется **в соседнюю папку**, чтобы исходное дерево и его SHA остались неизменными:

```bash
set -o pipefail
bash canonical/run_verify.sh 2>&1 | tee ../CRTT-T32-local-verification.log
```

Runner проверяет исходные SHA, контрольные случаи парсеров, точную версию Lean, компилирует 21 файл, проверяет разрешённые аксиомы и точные имена всех 542 целей, выполняет 13 конечных проверок, затем реально запускает `ReleaseMain.lean` и сравнивает его вывод с независимым конечным эталоном. Временные `.olean` и промежуточные логи создаются за пределами пакета и удаляются runner-ом.

При отсутствии Lean runner заканчивается кодом 127. Такой результат сохранён для первоначальной среды подготовки. В предоставленном полном журнале записаны успешные Lean-статусы для 21 модуля и CLI, а также финальная отметка PASS. Повторный Python-аудит этих логов прошёл; в согласующей пересборке компилятор не запускался. История и границы подтверждения приведены в [VERIFICATION_RU.md](VERIFICATION_RU.md).

Чтобы при собственном запуске сохранить внешние коды завершения, используйте Bash. Обе записи остаются за пределами проверяемой папки:

```bash
set +e
bash canonical/run_verify.sh 2>&1 | tee ../CRTT-T32-local-verification.log
crtt_pipeline_status=("${PIPESTATUS[@]}")
printf 'runner_exit=%s\ntee_exit=%s\n' "${crtt_pipeline_status[0]}" "${crtt_pipeline_status[1]}" > ../CRTT-T32-local-verification.exit.txt
```

Успех этой команды означает `runner_exit=0` и `tee_exit=0`; эти значения следует проверять вместе с журналом.

## 4. Повторить отдельные конечные проверки

Работайте в копии `canonical/`, если собираетесь сохранять новые результаты рядом с исходниками. Для контроля проекции используйте извлечённый CLI-сегмент полного предоставленного журнала:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 canonical/check_release.py --lean-log evidence/reconciliation/replay/runner_cli.raw.log
```

Аудит каждой секции Lean-журнала требует точного исходного модуля, соответствующего сегмента вывода и сохранённого кода компилятора. Готовые команды, сегменты, результаты и их SHA находятся в `evidence/recheck/`. Повторная обработка этих сегментов проверяет предоставленное свидетельство; это отдельная операция от запуска компилятора.

## 5. Повторить аудит всех предоставленных полных логов

```bash
python3 replay_evidence.py --output ../CRTT-log-replay
```

Выходная папка должна быть новой или пустой и находиться за пределами распакованного архива. Скрипт проверяет 21 исходный SHA, точные 542 имени, порядок модулей, соответствие общего и отдельных журналов, коды Lean из предоставленных audit-строк и фактический CLI-вывод против заново вычисленного эталона. Он запускает 45 Python-команд и сохраняет их аргументы, stdout/stderr, SHA и наблюдаемые коды возврата. Компилятор Lean не вызывается.

Сохранённый результат согласующей пересборки: [evidence/reconciliation/replay/log_review.json](evidence/reconciliation/replay/log_review.json). Абсолютные пути в аргументах команд фиксируют среду конкретного выполнения; относительные пути отчёта задают расположение приложенных файлов. Повторный запуск создаёт новый отчёт в выбранной внешней папке.
