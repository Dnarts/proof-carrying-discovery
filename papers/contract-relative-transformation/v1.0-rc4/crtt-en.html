Contract-Relative Transformation Theory

How to change methods during a search

While preserving proved guarantees: correct results, the ability to finish the work, and a record of the steps already taken.

Based on the preprint From Certified Discovery to Meta-Policy Closure
Aleksandr Strand
strandlex@gmail.com

Contract
What counts as an admissible result for the declared task.
Controller
The rules that govern how the search proceeds.
Meta-policy
A plan that determines whether to prepare an attempt to replace the controller.

The setting is a finite deterministic model. The “coins” below are accounting units, not measured seconds or bytes of memory.

Read in order ↓

An algorithm has already started work: it has checked some candidates, ruled out impossible ones, and kept the solutions it has found. Now another method is available. CRTT studies how to permit that replacement while preserving the meaning of the unfinished search — and how to check that the resources will cover it.

01 / First, define the task

Correctness is always relative to a contract

The contract specifies which actions are admissible in each state. A suitable method must satisfy those requirements. Three distinct obstacles can arise.

No suitable action

Operator barrier

The permitted class may contain no action that satisfies the contract. Even complete knowledge of the state cannot help in that case.

Too few distinctions

Representation barrier

The observation groups together states for which no single common admissible action can be chosen.

Selection goes wrong

Selection barrier

An admissible action exists and the observation is sufficient, yet the selection mechanism may still choose an inadmissible option.

These are different causes of failure. New observations help distinguish states; they do not create a missing operator. And the existence of a correct choice does not mean the current program will find it.

A running system raises further questions: whether a method can be transferred to a new task, what it costs to find and check a replacement, and whether enough resources will remain to finish. We will follow that sequence below.

Source: preprint, §§1–2: the contract and the three initial barriers.

02 / How much must be known?

An observation is sufficient when it supports an admissible choice

The exact state of the world need not be identified. It is enough that each group of states the observation cannot distinguish has at least one action admissible for the entire group.

The same action for the listed worlds
WorldsCommon actions
x₁ and x₂{B}
x₁ and x₃{A}
x₂ and x₃{C}
x₁, x₂ and x₃∅ — none

If the observation cannot distinguish any of the three worlds, no admissible action can be selected: every answer violates the contract in at least one world.

Any pair can be grouped together while keeping the third world separate. This gives three sufficient partitions: {x₁,x₂} | {x₃}, {x₁,x₃} | {x₂} and {x₂,x₃} | {x₁}. But a sufficient partition coarser than all three does not exist: it would have to group all three worlds together.

This is a collective obstruction: it is absent from every pair but appears in the group as a whole.

What the criterion establishes. It establishes the existence of a policy that chooses actions from observations, not the correctness of any particular selector. The general theorem assumes a nonempty action space and uses classical choice; the later finite constructions are considered separately.

Source: §2, Theorems 2.1 and 2.2; the triangle example.

03 / From selection to investigation

A method still needs a valid transfer to the new task

If the current observations are insufficient, further observations can be purchased. In the model, an investigation is a finite tree: query a feature, receive 0 or 1, follow the corresponding branch, and eventually choose an action.

For specified states, queries, prices and a depth limit, exhaustive search can construct a tree with optimal worst-case cost. This is optimality among the declared legal trees; it does not make the search itself inexpensive.

Now suppose a tree has already been found for task S, while the task to be solved is T. CRTT defines a transfer morphism: a compatible mapping of states, queries and actions. It preserves observation responses and respects the depth constraint, without increasing query prices or terminal losses.

Given such a morphism, the source tree can be translated to the target task with proved guarantees. Finding the morphism is a separate search. The finite algorithm enumerates query maps and action maps and constructively chooses a compatible source state for each target state.

What “complete search” means. It obtains a canonical representative for every admissible combination of query and action maps. It need not enumerate every possible state map. If the enumeration is exhausted and the canonical list is empty, no morphism exists in this specified class.

An example we will return to

In the artifact’s example, the source task has depth limit dS = 1, while the target has dT = 0. The definition of a morphism requires dS ≤ dT, so no transfer of this type exists. This does not mean that the target task has no solution by other means.

Ordinary enumeration may take many steps to prove that no transfer exists. A certified depth rule can close the same search earlier. We will use this example below to see how replacing the controller changes the cost.

Sources: §3: optimal investigation, transfer and canonical discovery; §8.2: the depth-obstruction example.

04 / Making use of a failed search

Compiling hard lessons: turn a dead end into a rule

Sometimes a partial query mapping already rules out every compatible source state for some target world. Extending the mapping cannot rescue that branch: adding constraints cannot bring excluded states back.

Step 1

Find the incompatibility

The row of compatible worlds is empty. This provides a concrete witness that the branch cannot be extended to a morphism.

Yw(ρ) = ∅

Step 2

Remove redundant constraints

An inclusion-minimal core K is extracted: the incompatibility remains, but deleting any remaining constraint removes it. The core need not contain the smallest possible number of constraints.

K ⊆ ρ

Step 3

Keep the pruning rule

Assignments containing K can now be rejected. The proof guarantees that no admissible extension to a morphism is lost.

K ⊆ ρ′ ⇒ the branch can be pruned

A recorded failure thus becomes a tool for future search. But usefulness has two aspects: the rule must be sound, and obtaining and using it must pay off. The first does not imply the second.

This is a result for a particular controller, set of tasks and fee schedule. It does not measure the “probability that learning is useless”. It motivates the next question: when is a more elaborate method worth paying for?

05 / Evidence for a decision

The right choice need not require an exact price

Consider two methods and two possible hypotheses about their costs. In the second world, both prices are higher by 100. The best method is still the same.

Method 1 is cheaper by one unit under both hypotheses. Its worst-case regret is zero. So to choose between these two methods, there is no need to distinguish the worlds. The exact eventual bill remains unknown, but that is a different question.

The guarantee concerns a specified finite catalogue of methods and a set of hypotheses containing the actual model. It cannot simply be extended to an unknown better method outside that catalogue.

A different certificate: a sufficiently narrow interval

Sometimes only proved cost bounds are known: L ≤ C ≤ U. These yield lower and upper bounds on the optimal worst-case cost of investigation: VL and VU.

If the gap satisfies VU − VL ≤ ε, the tree optimized for the upper bounds has worst-case cost at most ε above the true minimax optimum among the declared legal trees. Exact values for every cost are not required.

Two different guarantees. In the first table, one method is optimal under every hypothesis. The interval certificate establishes how close worst-case cost is to the minimax optimum. By itself, it does not promise small regret in every individual world. A small gap is a sufficient, but not a necessary, condition for this near-optimality.

Source: §5, Theorems 5.2–5.3: interval minimax bounds and decision-relative evidence.

06 / Replacement during execution

Lower cost is not enough. The transition must also be affordable

An unfinished search contains discovered certificates, receipts and remaining jobs. Replacing the controller must preserve all three components, including the work that still needs to be checked.

In this construction, the certified library of pruning rules changes while the base fees stay fixed. Rebuilding the queues preserves the meaning of the remaining jobs. The proposal already carries proofs that the replacement is sound, that its cost bounds are valid, and that its new completion reserve is sufficient.

Only then does the numerical gate operate. It neither synthesizes those proofs nor runs both controllers for free to compare their future bills.

  1. 1

    The check is affordable

    H + Rold ≤ B

    After paying H, enough reserve must remain to finish with the old controller, even if the proposal is rejected.

  2. 2

    The replacement is affordable

    H + K + Rnew ≤ B

    After paying for the check H and migration K, enough reserve must remain to finish with the new controller.

  3. 3

    Strict savings are proved

    H + K + Unew < Lold

    The check, migration and upper bound on the new bill together fall below the proved lower bound on the old bill.

Here B is the available balance; R is a sufficient reserve, not money already spent; L and U are sound bounds that need not be exact. The initial state must already satisfy Rold ≤ B.

Check deferred

B = 100

With H = 1 and a reserve of 100, the extra unit needed for the check is missing. The paid attempt is deferred; the debit is 0. The old state is retained.

Rejected for liquidity

B = 101

The check costing 1 is affordable. But another 1 for migration cannot be paid while retaining the new reserve of 100. Only the check is charged.

Replacement accepted

B = 102

The check and migration cost 2, the reserve of 100 is funded, and 1 + 1 + 1 < 7. The debit is 2; the new controller is installed.

A proposal can also fail the gain test: with H = 3, K = 4 and the same bounds, we get 3 + 4 + 1 = 8 ≥ 7. Even with a balance of 110 and funded reserves, the replacement is rejected: there is no strict saving. Only H = 3 is charged, and the old controller is retained.

Why the relationship between bounds matters

In a more general version, the proposal carries the paired bounds (7, 1) and (70, 64). With a combined check and migration charge of 2, both rows pass:

2 + 1 < 72 + 64 < 70

Taking the old lower bound 7 and the new upper bound 64 independently would lose useful information about their relationship. The original list requires a proof that at least one pair simultaneously bounds the actual old and new bills; the gain test is checked for every pair. The second row represents synthetic uncertainty, not a measurement from another world.

07 / The low_liquidity counterexample

Why spending one coin turns a bill of 4 into 10

Return to the depth-obstruction example. Finishing with the old controller costs 7; with the new one, 1. Both declared reserves are 100. The initial balance is 103, and proposal preparation, checking and migration each cost one unit.

The current meta-policy already calls for an attempt to replace the controller. Compare two paths: execute it immediately, or first spend one unit on a rejected upgrade to the meta-policy itself.

Losing an option costs more than the fee itself. The extra unit spent crosses the liquidity threshold. A beneficial replacement becomes unaffordable, so the old controller must finish the search. This is exactly what happens in the finite 4 → 10 example.

Why the balance can fall below the reserve of 100

The reserve is protected from investigation and replacement expenses so that the main task can still be finished. Completion itself is paid from that reserve. It is a sufficient upper bound on the future bill, not an untouchable amount that must remain forever.

Final balances of 99 and 93 are therefore valid. The accounts reconcile in both cases: 99 + 4 = 103 and 93 + 10 = 103. No resources have appeared or disappeared.

Two levels of economic accounting

For the root controller, Φ is the amount already debited plus the exact modeled bill for finishing with the current controller. Every connected finite history satisfies:

Φend + G = Φstart + OG is the net gain from accepted replacements; O is the cost of rejected attempts and external evidence.

The total cost is lower than immediately finishing with the original controller exactly when G > O. In the first scenario, 7 + 1 − 4 = 4; in the second, 7 + 3 − 0 = 10.

The meta-policy bill Ψ includes execution of its tree followed by completion of the search. It depends on which operations the tree can afford. After a rejected meta-upgrade, its change therefore cannot be reduced to the rejection fee alone. The paper proves monotone improvement in Ψ for histories with no rejected meta-upgrades; free deferrals are allowed.

Sources: §6.3: exact accounting at the root level; §7.2: the restriction on meta-policy monotonicity and the 4 → 10 counterexample.

08 / Bringing the guarantees together

The way replacements are selected can change too

The controller carries out the search. The meta-policy determines whether to pay for an observation, keep the controller, or prepare an attempt to replace it. It is represented by a finite tree, and that tree also admits certified replacement.

Accepting a meta-upgrade requires a proof that it reduces the all-in bill relative to the exact current state. The upgrade fee is already reflected in the new state after payment; it must not be added again. Installing a new tree does not execute it and does not, by itself, replace the root controller.

The final protocol is specific: run a finite list of meta-upgrade plans, interpret the last installed tree once, then finish the main search using the funded reserve. The theorem applies to fixed finite tasks, a fixed evidence provider and well-typed proposals.

  • The search is exhaustedThe queue of remaining jobs is empty. The initial continuation must be funded.
  • The results are completeA canonical morphism belongs to the result if and only if it belongs to the reference list discoverAll(S,T). List order and multiplicity need not match.
  • Impossibility is characterized exactlyAn empty final list is equivalent to the absence of a morphism in the specified transfer class. This does not establish the impossibility of every other method.
  • Resources are accounted forThe sum of the available balance and accumulated modeled debits is conserved.
  • History is preservedAdmissible transitions preserve the specified relations between certificates, receipts and logs. The guarantee concerns the formal state history.

Where proposal proofs come from

Useful bounds need not be exact, but they must be proved sound. Some certificates are constructed within the stack: for example, the static potential P(C,f) supplies a sufficient reserve. The exact bill for a finite continuation is also constructively defined, but obtaining it may be expensive.

A general inexpensive way to synthesize sufficiently strong comparison bounds and all proposal factories is not provided here. They are supplied with proof obligations tied to the current state. Providing an input slot does not establish that the input is easy to produce.

Scope of the results

The verifier, root contract, evidence provider and base fees are fixed. The permitted changes affect declared certified rule libraries and finite meta-policy trees. These results do not establish arbitrary code transfer, unbounded self-improvement, physical performance gains for neural networks, or file durability after a crash.

The central idea

A change of method becomes a verifiable transition: preserve the meaning of the work still to be done, supply sufficient evidence, and pay for the change while retaining enough resources to finish the task.
